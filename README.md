## 1. Learn Git Branching

Пройдите на сайте [Learn Git Branching](https://learngitbranching.js.org/?locale=ru_RU):

- раздел «Основы» — обязательно;
- первый раздел по удалённым репозиториям — обязательно;
- второй раздел по удалённым репозиториям — по желанию.

Сохраните скриншот с результатом прохождения обязательных разделов.

## 2. Локальная практика

Создайте локальный Git-репозиторий и на собственном примере попробуйте:

- `add`;
- `commit`;
- `checkout` или `switch`;
- `merge`;
- `rebase`;
- интерактивный `rebase` и squash коммитов;
- `cherry-pick`;
- разрешение конфликта;
- восстановление потерянного коммита через `reflog`.

Сценарий работы придумайте самостоятельно. Вы должны понимать, что делает каждая команда, и уметь объяснить свои действия.

После выполнения сохраните reflog в файл:

```bash
git reflog --date=iso > git-reflog.txt
```

Файл `git-reflog.txt` необходимо добавить в итоговый репозиторий.

## 3. Проект

1. Создайте аккаунт на GitHub, если его ещё нет.
2. Сделайте fork этого репозитория.
3. Клонируйте свой fork на компьютер.
4. Создайте отдельную ветку для работы.
5. Выберите одну из задач:
   - вычисление факториала;
   - вычисление N-го числа Фибоначчи.
6. Реализуйте простой первоначальный вариант алгоритма.
7. Сделайте несколько осмысленных коммитов.
8. Улучшите или ускорьте алгоритм в своей рабочей ветке.
9. Будьте готовы объяснить, что именно вы изменили и почему новый вариант лучше.

В репозитории должны находиться:

- исходный код программы;
- `git-reflog.txt`;
- краткая инструкция по запуску;
- объяснение выполненной оптимизации.

## 4. Сдача работы

Опубликуйте рабочую ветку в своём fork и создайте Pull Request:

- **откуда:** рабочая ветка вашего fork;
- **куда:** ветка `master` исходного преподавательского репозитория.

Название PR:

```text
[<номер группы>] <ФИО>
```

Не создавайте draft-PR. Открывайте Pull Request только тогда, когда работа полностью готова к проверке.

В описании PR укажите:

```markdown
## Информация

ФИО:
Группа: <номер группы>
Выбранная задача: факториал / Фибоначчи

## Что сделано

Кратко опишите первоначальный алгоритм и выполненную оптимизацию.

## Проверка

- [ ] Пройдены обязательные разделы Learn Git Branching
- [ ] Приложен скриншот прохождения
- [ ] Выполнена локальная практика с Git
- [ ] Разрешён конфликт
- [ ] Выполнены rebase, squash и cherry-pick
- [ ] Потерянный коммит восстановлен через reflog
- [ ] В репозиторий добавлен файл `git-reflog.txt`
- [ ] Программа запускается
- [ ] Оптимизация описана
```

Скриншот Learn Git Branching приложите к описанию PR.

## Очерёдность сдачи

Временем сдачи считается время создания готового Pull Request.

Пустые и незавершённые PR не позволяют занять место в очереди. Если на момент создания PR обязательные требования не выполнены, работа отправляется на доработку и не считается сданной, пока не внесены все исправления.

Первые пять студентов определяются по времени создания корректно выполненных Pull Request.

Коммиты, добавленные после создания PR, считаются исправлениями и не учитываются при определении первоначальной готовности работы.
