# Отчёт о практике Git

Работу выполнил Павленко Богдан, группа ДЭ 21-25. Основная рабочая ветка —
`work-branch`.

## Выполненный сценарий

| Операция | Что было сделано |
| --- | --- |
| `add`, `commit` | Исходный код, тесты и документация добавлялись в индекс и сохранялись отдельными осмысленными коммитами. |
| `switch` | Созданы ветки `docs/run-guide`, `practice/output-label`, `practice/rebase` и `feature/large-number-test`; между ними выполнялось переключение. |
| `merge` | Ветка с инструкцией объединена с `work-branch` через merge-коммит. |
| Разрешение конфликта | Две ветки по-разному изменили строку вывода. После конфликта оставлен вывод только числа, потому что он удобен для автоматической обработки. |
| `rebase` | Коммит с началом отчёта из `practice/rebase` перебазирован поверх коммита с тестами, затем применён fast-forward merge. |
| Интерактивный `rebase`, squash | Два последовательных коммита оптимизации объединены в один `perf: optimize Fibonacci calculation`. |
| `cherry-pick` | Коммит с тестом для `fibonacci(100)` перенесён из `feature/large-number-test` в рабочую ветку. |
| `reflog` | Коммит с этим отчётом намеренно убран командой `reset --hard`, найден в `git reflog` и восстановлен по хешу. |

## Что делают команды

- `git add` помещает выбранное состояние файлов в индекс для следующего коммита.
- `git commit` создаёт объект коммита со снимком индексированных файлов,
  автором, сообщением и ссылкой на родительский коммит.
- `git switch` меняет текущую ветку или создаёт новую с ключом `-c`.
- `git merge` объединяет истории веток. Если одни строки изменены несовместимо,
  Git останавливает слияние до ручного разрешения конфликта.
- `git rebase` переносит коммиты на новую базу, создавая для них новые хеши.
- `git rebase -i` позволяет отредактировать последовательность коммитов;
  команда `squash` объединяет выбранный коммит с предыдущим.
- `git cherry-pick` применяет изменение из конкретного коммита к текущей ветке.
- `git reflog` хранит локальный журнал перемещений ссылок и позволяет найти
  коммит, который перестал быть видимым в обычной истории ветки.

## Ответы на дополнительные вопросы

### Кто и зачем написал Git?

Git создал Линус Торвальдс в 2005 году для разработки ядра Linux. Нужна была
быстрая распределённая система контроля версий после прекращения бесплатного
использования BitKeeper проектом Linux.

### За какое время была написана первая версия?

Рабочий прототип появился примерно за десять дней. Уже в первые недели Git
начали использовать для разработки ядра Linux.

### Чем Git отличается от других систем контроля версий?

Git — распределённая система: полный репозиторий и его история находятся у
каждого разработчика. Большинство операций выполняется локально; сервер нужен
для обмена изменениями, но не является единственным местом хранения истории.

### Как Git хранит изменения?

Git использует адресуемую по содержимому объектную базу. Файлы представлены
объектами `blob`, каталоги — `tree`, а коммиты указывают на корневое дерево,
родителей и метаданные. Идентификатор объекта вычисляется из его содержимого.
Git логически хранит снимки состояния проекта, а не только последовательность
текстовых различий.

### Что такое GitHub, GitLab и Bitbucket?

Это платформы для размещения Git-репозиториев и совместной разработки. Помимо
Git-хранилища они дают Pull/Merge Requests, ревью, задачи, управление доступом,
CI/CD и другие командные инструменты.
