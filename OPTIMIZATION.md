# Почему итеративная версия быстрее

## Исходный алгоритм

Первый коммит содержит прямую рекурсию:

```python
if n < 2:
    return n
return fibonacci(n - 1) + fibonacci(n - 2)
```

Например, при вычислении `F(5)` значение `F(3)` требуется и в ветке `F(4)`,
и непосредственно в `F(5)`. Рекурсия заново вычисляет оба одинаковых
поддерева. Число вызовов растёт как `Theta(phi**n)`, где
`phi = (1 + sqrt(5)) / 2`. Глубина стека — `O(n)` вызовов.

Полная исходная программа сохранена без изменений в
[examples/fibonacci_recursive.py](examples/fibonacci_recursive.py).

## Выполненное изменение

Основная функция теперь хранит только два соседних числа:

```python
current, following = 0, 1
for _ in range(n):
    current, following = following, current + following
return current
```

Перед шагом с номером `k` в `current` находится `F(k)`, а в `following` —
`F(k + 1)`. Одновременное присваивание переносит второе число в первое,
а их сумму — во второе. После `n` шагов `current` равен `F(n)`. При `n = 0`
цикл не выполняется, поэтому возвращается правильное значение `0`.

Получается ровно `n` сложений: `O(n)` арифметических операций и постоянное
число переменных, то есть `O(1)` памяти в обычной учебной модели с целыми
числами фиксированной стоимости. Исчезают повторные вычисления и рекурсивные
вызовы.

Python хранит целые числа произвольной длины. У `F(n)` линейное по `n`
число бит, поэтому два накопителя занимают `O(n)` бит. Если учитывать
стоимость сложения больших целых, сумма работ всех шагов составляет
`O(n**2)` битовых операций. Формулировка «постоянное число переменных»
точнее безусловного утверждения о постоянной памяти в байтах.

## Проверка результата

Команда `python -m unittest discover -s tests -v` проверяет в том числе
`F(0) = 0`, `F(1) = 1`, `F(10) = 55` и
`F(100) = 354224848179261915075`. Для индексов от `0` до `20` результаты
сравниваются с сохранённой рекурсией. Проверяется также интерфейс командной
строки и отклонение отрицательных, дробных и текстовых аргументов.

## Воспроизводимый замер

```bash
python benchmark.py
```

Скрипт использует `timeit.repeat` для индексов `10`, `20`, `30`. Для каждого
алгоритма берётся минимум из пяти повторов, поделённый на число вызовов:
3 вызова рекурсии и 10 000 вызовов итерации в одном повторе. Много вызовов
быстрой функции уменьшает влияние точности таймера. Перед замером скрипт
проверяет равенство результатов.

Время включает вызов Python-функции и проверку аргумента. Оно зависит от
компьютера, версии Python и фоновой нагрузки; отношение времён описывает
данный запуск и не является обещанием ускорения на другой машине.
Конкретный контрольный результат сохранён в
[docs/benchmark-results.txt](docs/benchmark-results.txt).
